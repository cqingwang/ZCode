# 修复：Web 直连独立 Server 的已有会话续聊报 project.host-offline

## 技术栈与范围
- TypeScript / Node 24，`packages/services/src/project/index.ts` 的 Host 项目路由。
- 不改 CLI 协议、不改远端单 root 约束、不新增持久化字段。

## 现象与证据
- Web 直连独立 Server（`/ws`，`web-remote-replayable`）续聊已有会话时，前端提示“发送失败，请稍后重试”，详情 `project.host-offline`。
- 服务日志：`project.resolveSessionDirectories FAIL Error: project.host-offline`，栈顶为 `route`。
- 独立 Server 的持库 Host 为 `remote:server:pve`；Web 客户端没有 workspaceIdentity，Composer scope 的默认 `hostId` 为 `local`。
- `createProjectService.route` 把任何不等于持库 Host 的 `hostId` 都当作外部 Host；独立 Server 没有 `resolveHost`，于是抛 `project.host-offline`。

## 根因假设
- 直连客户端的 `local` 语义是“当前连接的 Host”，不是另一台本机 Host。独立 Server 只有持库 Host，`local` 应归一为持库 Host。
- 与 EM-2026-10-21-07 的 task-group 归一规则一致：只有无 workspaceIdentity 的 `local` 默认值才归一；显式远程 Host 仍走原路由。

## 设计
- 在 `createProjectService` 内集中归一 `hostId`：`ownerHostId` 非 local 时，`local` → `ownerHostId`。
- `route`、`prepareSession`、`ensureDefaultProject`、`resolveSessionDirectories` 等全部复用同一入口，避免只修一条调用链。
- 不改变 `ownerHostId` 的存储身份；显式其他 Host 仍必须由 `resolveHost` 提供，缺失继续 fail-fast。

## 验证门禁
- 新增回归：远端持库 Host + `resolveSessionDirectories(..., "local")` 必须命中本 Host 仓储，且不调用 `resolveHost`。
- 更新既有“客户端 hostId 不能改变持库身份”用例：`local` 归一后仍使用持库仓储，不路由到外部 Host。

- `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`。
