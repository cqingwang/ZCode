# Web 抽拉侧栏收起/展开交互 实施计划

## 需求拆解

1. Web 模式下左侧任务栏抽拉面板支持收起/展开：在左侧面板右延边加一个三角形小角标，点击切换收起/展开（桌面与普通 Web 窗口同样生效）。
2. 移动端屏幕大小的窗口：收起后悬浮一个可拖动的操作 banner（默认左上角悬浮），点击 banner 展开侧栏；展开后 banner 隐藏，再次收起后 banner 重新出现。

## 现状与唯一写入路径

- 侧栏显隐唯一状态：`useAppPanels.ts` 的 `isSidebarVisible`（`useState(true)`），唯一入口 `handleToggleSidebar`；经 `App.tsx` → `WorkspaceShellLayout` → 面板容器 / `DesktopTopOverlay`。
- 收起态由外层 CSS 变量 `--workspace-sidebar-panel-width` 收为 `collapsedSidebarWidthPx`(0/4px) 实现，面板容器带 `overflow-hidden` 与 `transition-[width,opacity]`；宽度本身持久化在 `zcode:workspace-shell:sidebar-width-px`。
- 桌面端收起后的展开入口目前是 `DesktopTopOverlay` 左上角按钮；移动端窗口没有独立入口。

## 决策

- 状态所有权不变：仍由 `useAppPanels` 唯一持有，新增「持久化 + 视口默认值」两条派生规则，写入路径唯一（`handleToggleSidebar`）。
- 领域逻辑（初始收起判定/偏好读写/banner 位置钳制）下沉到纯函数模块 `packages/ui/src/lib/workspaceSidebarCollapse.ts`，无 IO、storage 注入，直接 `node --import tsx --test` 单测（与 `packages/ui/test` 既有入口一致）。
- 移动端判定用 `matchMedia("(max-width: 767px)")` + `useSyncExternalStore`，与仓库既有 `max-md` 断点语义一致；SSR/无 matchMedia 环境返回 false。
- 路径降维：不做抽屉遮罩/新状态机。移动端收起态把侧栏面板改为 `absolute` 覆盖层（复用既有 width 过渡即得到抽拉动画），展开态保持原流式布局；banner 只做 fixed + pointer capture 拖动 + 吸附左右边，点击与拖动用位移阈值区分。
- 桌面端角标：展开态挂在侧栏面板内右延边（`right-0`），收起态挂在 shell 左边缘；`overflow-hidden` 下不会溢出。移动端展开态同样显示角标（作为收起入口），收起态由 banner 承担展开入口。

## 核心函数签名

- `resolveWorkspaceSidebarCollapsed({mediaMatchesMobileViewport, storedPreference}) => boolean`
- `readWorkspaceSidebarCollapsedPreference(storage) => boolean | null`
- `persistWorkspaceSidebarCollapsedPreference(collapsed, storage) => void`
- `shouldShowWorkspaceSidebarFloatingBanner({isMobileViewport, isSidebarCollapsed}) => boolean`
- `clampWorkspaceSidebarBannerOffset(offset, {viewportWidthPx, viewportHeightPx}) => {left, top}`
- `useWorkspaceSidebarMobileViewport(): boolean`
- `<WorkspaceSidebarCollapseTab side expanded onToggleSidebar />`
- `<WorkspaceSidebarFloatingBanner onExpandSidebar />`（单图标 44x44 圆钮；展开只在 click 阶段触发，pointerup 仅落位持久化——触摸输入下 touchend 会重新命中遮罩）
