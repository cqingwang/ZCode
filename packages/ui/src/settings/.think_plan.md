# 使用统计标题行展示当前应用版本 实施计划

## 需求拆解

1. 在设置页「使用统计」分区标题行（即包含「应用用量 / 个人套餐」tab 的那一排）的最右侧，展示当前应用版本号。
2. 版本号来源为唯一真实源：`@zcode/shared` 的 `ZCODE_VERSION`（由各 bundler 通过 `__ZCODE_VERSION__` define 注入，Web 端取根 `package.json` version，桌面端取构建元数据 appVersion）。

## 现状与唯一写入路径

- 「使用统计」标题行位于 `packages/ui/src/SettingsPage.tsx` 的 `activeSection === "usage"` 分支：
  外层 `flex flex-wrap items-center justify-between gap-3` 目前只有一个左侧子容器（标题 + `SettingsUsageProviderTabs`），右侧为空，天然可承载右对齐的版本展示。
- 版本常量 `ZCODE_VERSION` 已在 `packages/shared/src/version.ts` 统一定义，`packages/ui` 通过 `@zcode/shared` 公开入口消费（如 `CodingPlanEmbeddedWebviewDialog.tsx`）。
- 无新增状态：版本是构建期常量，纯展示，不引入 store / hook / 服务调用。

## 决策

- 展示位置：使用统计标题行右侧（`justify-between` 的第二子元素），`text-ui-sm text-foreground-subtle`，符合 DESIGN.md 中「secondary copy 用 text-ui-sm + foreground-subtle」的元数据语义。
- 版本归一化下沉到纯函数 `packages/ui/src/lib/appVersionLabel.ts` 的 `resolveAppVersionLabel`：去空白、空值回退 `--`、缺少 `v/V` 前缀时补 `v`。无 IO、无 React 依赖，可直接 `node --import tsx --test` 单测。
- 文案走 i18n：`settings.usage.appVersion` = `版本 {version}` / `Version {version}`，版本值由纯函数注入。
- 新增 `TID_SETTINGS_USAGE_APP_VERSION` test id 供 E2E 断言。
- 路径降维：不新增组件文件、不新增 hook，仅在既有标题行加一个受 i18n 与纯函数约束的展示节点。

## 核心函数签名

- `resolveAppVersionLabel(rawVersion: string | null | undefined): string`

## 回归测试

`packages/ui/test/appVersionLabel.test.ts`：先跑红（模块缺失），实现后跑绿；覆盖纯数字补 `v`、已有 `v/V` 前缀不重复、去空白、空值回退 `--`。

## 附带修复：开发环境端口冲突

- 症状：`pnpm dev:web` 启动后端时 `EADDRINUSE :::3030`，因为 `3030` 已被 systemd `zcode.service`（生产后端）占用。
- 根因：开发链路直接复用生产默认端口 `3030`。
- 修复：新增 `scripts/dev-web.mjs` 包装器，统一注入 `PORT=3031`（server 监听）与 `ZCODE_DEV_SERVER_PORT=3031`（vite `/ws`、`/api` 代理目标），可用 `ZCODE_DEV_SERVER_PORT` 覆盖；`packages/web/vite.config.ts` 的代理目标改为读取该变量。生产默认端口 `3030` 保持不变。
